# Voting guide: agent instructions

*Last verified: 2026-11-13 (paths and the after-election state; three long reference sections moved beside the code they describe, so this file fits what Codex reads).*

A public, one-page guide to the Nov 3, 2026 general election for Kevin's friends and family: enter a ZIP, see the next step and its date, every item on your ballot as a row with your trusted sources' picks beside it, decide, and leave with a cheat sheet. Since the polls closed it leads with results: each race on your ballot shows the count from official feeds beside your pick (`src/results.ts` reads the file the results fetcher below serves; `src/model/results.ts` holds the honesty rules, such as no "won" until the source marks its count complete). Live at https://vote.kevinhg.com (since Oct 19, 2026; the original https://voting-guide-silk.vercel.app still serves the same site). Vite + vanilla TypeScript, no framework, no cookies, no accounts; crash reports go to Sentry, errors only and scrubbed, and visits are counted with Vercel's cookie-free Web Analytics, nothing personal sent (both below). This repo is public: nothing private goes in it. Research, plans and the reasons behind the rules live in the sibling repo `~/DevKev/personal/voting-guide-workbench` ("the workbench" below).

## Run and test

Node 20+. If `node --version` shows an old version, prefix commands with `export PATH=/usr/local/opt/node@22/bin:$PATH;` (a stray 2016 node at `/usr/local/bin` shadowed the real one on Kevin's personal Mac until Oct 19, 2026). Use preview ports 4173 to 4189: Node's `fetch` refuses a few ports on the web's "bad ports" list (4190 is one, as are 6000 and 6665 to 6669), and the sweep then fails with "bad port".

```sh
npm ci && npm run playwright:install
npm run build                      # data bundles + typecheck + production build
npx vite preview --port 4173       # then, against it:
npm run test:model                 # contracts, no browser: save links, districts, lenses, verdicts, fills (~1s)
npm run test:e2e                   # scripted taps at 380px (~2 min)
npm run sweep                      # every ballot the guide can show (74) checked against the data; MODE=full for every district variant
node tests/perf.mjs                # biggest ballots at 4x CPU throttle: taps must paint under 250ms
npm run shots                      # review screenshots of the test ballots into .tmp/shots/ledger/
node tests/pages.mjs               # the pages for search engines, no browser (after npm run build, dist/ too)
node tests/pages-browser.mjs       # those pages as a crawler reads them, and their buttons, against the preview
scripts/ship.sh --gates-only       # all local gates in one go
```

Crash-report checks in the e2e need a build with a DSN: `VITE_SENTRY_DSN=https://0e2e0e2e0e2e0e2e0e2e0e2e0e2e0e2e@o0.ingest.us.sentry.io/0 npm run build`, then `SENTRY_E2E=1 npm run test:e2e` (CI and `ship.sh` do both; project 0 takes nothing).

`BASE` points any browser check at another server (a Vercel preview, production). `?today=2026-11-03` pretends it's that date. `?try=fresh|aunt|straight|sources` shows a scenario on whatever ballot opens and never saves anything.

## Where things live

- `data/` is the only copy of the research data. `scripts/build-data.mjs` validates it into `public/data/` bundles (bad records are skipped and reported, never fatal) and counts each place's and state's coverage into `index.json` (`scripts/coverage.mjs`: sources on that ballot, how many with picks, local ones, its own races with any pick, the newest row date; `tests/model.mjs` pins them to the app's own ballot); `scripts/check-data.mjs` and `scripts/check-addresses.mjs` are the data gates. New optional fields must be passed through and shape-checked in build-data and typed in `src/types.ts`. An endorser's `blocked: true` with a one-line `blocked_note` (Oct 25) marks a source whose site shows a bot check to anything that isn't a browser; it reads like a paywall ("Couldn’t read"). A place's `county_fips` (Oct 29) lists the Census county codes its voters all live in (five digits, state then county: the City of St. Louis is `29510`, St. Louis County beside it `29189`, and the Census calls both "St. Louis"; check-data's `place-county-fips` holds each to the place's own state code), and `zip_outside` names a ZIP of its that also reaches a town the guide doesn't cover (`{"63120": "Pine Lawn, in St. Louis County"}`, `place-zip-outside`); build-data puts both in the index, so the first page can use them before a bundle loads. A place's `local_picks_checked` (Oct 29; Kevin: "request city is based on whether we've done a robust run for that spot not the number of sources we've found") records a hard look for its own papers' and groups' picks that came up empty: `{"on": "2026-10-29", "where": ["The Tennessean", ...]}`, set by the run that looked and naming only what it checked. While the place is thin (`model/coverage.ts`), its coverage card says we looked, when and where, and asks nothing; a local pick found later makes the place full by itself, so the date never hides one. Build-data puts it in the index too, beside the coverage it speaks for.
- `src/ballot.ts`, `src/state.ts`, `src/geo.ts`, `src/util.ts`: the model. `buildBallot` decides what is on a ballot (statewide items, place items, district questions, "may apply"). Don't replace it with a shortcut over `place.order`.
- `src/model/`: rules the views use. `labels` (titles, seat labels, courts, pick words, pass thresholds), `lens` (the chip presets over your sources, in step 2 and the ballot's Edit sheet; Nov 2, Kevin: LA friends "want union endorsements", so a fourth chip, Unions, is every `type: "labor"` source on the ballot; counting police and deputies' unions in it was the build brief's call, which Kevin knows of and can change. Each source is in one chip at most (`chipOf`), so a tap moves only its own chip: a labor council rated left by its mission is in Unions, not Progressive, and the sources sheet still lists it under its lean. Where that leaves Progressive with nothing, as in Tallahassee, the sheet says "Apart from unions, no progressive groups ..." (`emptyNote`). A model check taps every chip on every ballot. Nov 3: two reviews found chips that shared sources misbehaving, so the sharing was cut, not patched again), `tally` (the verdict column), `bulk` (fills with undo), `judges` (official reviews and the section's plain answer), `plan` (the next step from the state file; a place's own `early_in_person` window wins over the state's when every place on the ballot agrees), `search` (Oct 28: the page's one forgiving matcher, for the sources sheet and the plan's dates, ID and what-ifs: as you type, stems, a typo or two, everyday words for the data's words in `WORDS`; `all` for names, `best` for the what-ifs: heads first, full text only when that finds nothing), `coverage` (how covered a ballot is in plain words, the thin-place rule, and one-tap requests remembered per device), `adds` (a requested source on the requester's ballot before the merge, from its branch preview; `app.ts` swaps it in place, never through `resetUI`), `address` (what a Census match sets: district questions, "may apply" races on or off the ballot as `mine` or `notMine`, and the "Set from your address" line kept as `addrNote`, which names only the races the address put on the ballot; never the address).
- The address lookup and the district maps (Austin, Travis, Williamson, Dallas and Harris counties): which ballot an address belongs on, what the Census and the county maps settle, and why neither ever overwrites the voter's own answer. The code is `src/geo.ts`, `src/model/address.ts`, `src/model/maps.ts` and `scripts/maps/`; the rules are in `src/model/AGENTS.md`, so read it before changing any of them. Pull the maps again before an election: counties split precincts (check-data warns 30 days after a pull).
- Poll times are local: `plan.ts` keeps each state's time zones, the main one first. A new place in a state's other zone (Pensacola is Central in Eastern Florida) needs a line in `PLACE_ZONE`, or its "polls closed" moment is an hour off. A state whose polls close at one moment in two zones writes both in `polls_close` ("7:00 PM Central (8:00 PM Eastern)", Tennessee): `closeOf` keeps both on a ballot or state page that spans the zones and gives a place in the first zone its own "7 PM". A place in the second zone (Knoxville, Eastern) would also read "7 PM" and show polls closed an hour early, so teach `closeOf` and the closing check that zone's time before adding one. An opening time that isn't a plain time (each county sets its own) is never shown.
- `src/views/`: string templates, one file per part of the page. Beside them in `src/`: `render.ts` paints regions and single rows; `actions.ts` holds every `data-act`; `app.ts` the flows; `main.ts` boot and the tap handler (tuned on phones; keep it).
- `src/motion.ts`: the little motion there is. A tapped row's header stays put while its panel grows open (200ms) and folds away (160ms); a pick draws its tick; jumps glide and mark where they land; sheets slide; under "Hide races I've decided" a decided row shows its pick for a beat (`BEAT_MS`, 900ms, in `actions.ts`), then folds away (220ms) while the rows under it slide up, or its finished section folds under its band. Everything else a tap opens or closes in place (a section folding under its band, "Show" lines, the plan's details, the address form, the first page's switches, "Not on your ballot") goes through `glide`, which moves each named box from its old height to its new one (Kevin, Oct 21: nothing should snap). Only transform, opacity and one container's height animate, through the Web Animations API, so a repaint just drops an animation in flight; under `prefers-reduced-motion` everything lands at once in the same end state.
- Crash reports (Oct 25): `src/errors.ts` (main bundle, imported first) keeps the problem report's errors and, once the page has loaded and gone idle, fetches `src/sentry.ts`, a chunk of its own (about 24 KB gzipped), only in a production build with `VITE_SENTRY_DSN` (Vercel production and preview). `src/scrub.ts` holds what may leave; read its header before changing anything there, since the How text's privacy line promises it. The address check is one rule that fails closed (`errors.holdsPrivate`); keep it one rule. The chunk imports nothing from the page's bundle, so a start-up crash still reports. Source maps only with `SENTRY_AUTH_TOKEN` (never `VITE_`), deleted after upload. Off switch: remove `VITE_SENTRY_DSN` in Vercel and redeploy. https://khg-y1.sentry.io/projects/voting-guide/
- Visit counts (Oct 28; Kevin: "I would like the telemetry ... Let's turn it on."): `src/stats.ts` loads `@vercel/analytics` (the loader pinned; Vercel serves the script itself) only when the host is `kevinhg.com` or `*.vercel.app`, once the page has loaded and gone idle, from a chunk of its own (about 1 KB gzipped), so local dev, `vite preview` and the tests never load it. Vercel's script sends `location.href` whole; `beforeSend` (`cleanUrl`) cuts it to origin and path and drops an event whose path still holds five digits in a row or an at sign (only the path: a preview's host can hold five digits). The referring site goes as its origin only: Vercel's script reads `document.referrer` after `beforeSend` and sends another site's whole (the linking site decides how much that holds; our Referrer-Policy only governs links out), so `startStats()` shadows `document.referrer` on the page with `referrerOrigin` before the script loads, and loads nothing if that doesn't take. Pushing a view keeps the path, so Vercel's own pageview fires once per load; the screens are counted as events. `track(name, data)` sends four events, typed in `stats.ts` `Events` and the dashboard's vocabulary, so keep names and values stable: `ballot` `{ state, how }` (the state code only, never the place: Ballwin, Clayton and Webster Groves each come from one ZIP in the index, as does every set of several places like DC's wards or Aurora and Denver, so a place would name the ZIP typed, while any ZIP in a state opens at least its statewide ballot; how `zip`, `address`, `shared`, `returning`, `list`, `page`), `request` `{ kind }` (`city`, `picks`, `source`, `report`, `follow_up`, only once the post went out), `view` `{ name }` (`start`, `ballot`, `plan`, `share`, `reader`, on each change of screen, `app.ts viewed()`), `share` `{ act }` (`made`: the "Save a link to my picks" panel opened, each time it opens; `opened`: a save link opened a ballot). A value must be a short plain token and never holds five digits in a row, or the event is dropped: never a ZIP, an address, a Census answer, a pick, a contact or anything typed. On a Vercel host, events from before the script loads (a save link or a returning ballot opens during boot) wait in memory and go once it has. The How text's "Your privacy" item promises all this (model tests pin its words). e2e, sweep, perf and shots answer `/_vercel/insights/*` with an empty script, so a run against a preview or production never fetches the real one; the e2e's visit-count blocks stub `window.va` on localhost and serve the build as vote.kevinhg.com with a stand-in script that builds its payloads the way Vercel's does, to run the whole path (an incoming referrer with a ZIP in its query included). Off switch: turn Web Analytics off for the project in Vercel, or take `startStats()` out of `main.ts`. Dashboard: https://vercel.com/kevinhg/voting-guide/analytics
- Search engines and AI assistants (Oct 28; the `noindex` of Oct 16 is gone): `scripts/build-pages.mjs`, after `vite build`, writes a static page per place (`/austin-tx`) and state (`/texas`) from `src/pages/site.ts`, through the app's own model, plus the sitemap, robots.txt, llms.txt, 404 and IndexNow key; their headers say what they may and may not carry (never a pick, an endorser's name, a lean or `zip_caveats`). A page's button is `/?place=<id>` or `/?state=<ST>` (`main.ts`, counted as `how: 'page'`). `scripts/discovery.json`: the IndexNow key and the verification tokens. `ship.sh --after-merge` pings IndexNow with the pages that changed.
- Results fetcher (Nov 3, 2026): `results-worker/` is a Cloudflare Worker on Kevin's personal account that reads official county feeds and serves the counts the results view shows. It deploys with its own `results-worker/deploy.sh` (which refuses any other Cloudflare login), never with the site, and its data never goes through a pull request. Its rules (the county maps, when a county's numbers go public, the alerts, the stop switch) are in `results-worker/AGENTS.md`.
- `tests/`: `model.mjs` + `model-ledger.mjs`, `e2e.mjs`, `sweep.mjs`, `perf.mjs`, `shots.mjs`, `pages.mjs` + `pages-browser.mjs`.
- The look is three materials: paper (Blender renders in `public/paper/`, made by `scripts/paper/`; the sheets' torn bottom `sheet-bot.webp` is `sheet.webp` flipped, and the bottom bar's torn top is cut from the same outline; its README says how to regenerate, and `bake.py` writes the block between `paper:start` and `paper:end` in `src/styles.css`, so don't hand-edit it), one printed green ink for headings (Archivo, with a speck mask), and pen for rules, boxes and ticks. Print and dark mode swap through tokens.

## How changes ship

Branch, pull request, CI (`.github/workflows/ci.yml`: data gates, model tests, build, e2e, sweep), an independent review, then a squash merge. Pushes to `main` deploy to the live site, which friends use, so nothing merges without the gates green on the final commit. Vercel builds a preview for every branch (`voting-guide-git-<branch>-kevinhg.vercel.app`); run the sweep against it before merging.

### Test in proportion to the change

Kevin, Oct 20: tests were costing a lot of time, money and compute. CI runs every gate on every pull request at no cost (the repo is public), so local runs only need to catch sooner what CI would catch, not repeat it. The expensive parts are multi-agent reviews and full local gate runs every round.

- **Copy, CSS or data wording:** `npm run build` (the typecheck) and `npm run test:model` (about 1s). Push; CI does the rest.
- **A view or a flow:** those two, plus a short script or the e2e block that covers the change. Push; CI runs the full e2e and sweep.
- **Ballot building (`ballot.ts`, `geo.ts`), the save link or storage, districts, or data shape:** the full local gates (`scripts/ship.sh --gates-only`, with `--full` for district changes) before pushing.
- **`tests/perf.mjs`:** only when render or tap paths change.
- **Review:** one reviewer for routine work. Run a multi-agent review (Opus reviewers, never Fable in a fan-out) only for storage, ballot logic or the address lookup, and stop it once it has answered the question.
- **Don't rerun a gate that passed on the same code.** The bar for merging doesn't change: CI green on the final commit.

## Rules that do not bend

The reasons are in the workbench's FOUNDATION.md.

- No real person's street address anywhere: data, code, tests, notes. Public offices and polling places only, through the allowlist.
- Every fact has a source URL. Confidence is marked honestly (verified, sourced, unverified).
- Nonpartisan and parallel: the same fields for every candidate, quote rather than characterize, no recommendations from us. The default lens is papers and nonpartisan guides; anything partisan is the voter's choice.
- Lean labels come only from outside ratings, official party status or a group's own stated mission, never from whom it endorses.
- Endorsement states stay distinct: endorsed, took no stand, no picks found, not checked yet.
- No red or blue in the UI; party is text, lean is a neutral five-step scale plus a word. Color has one job each: gold = your pick, sage = your sources agree, clay = they disagree, dusk = the frame and official reviews.
- No all caps (no `text-transform: uppercase`), no em dashes in guide copy, plain words for a smart 16-year-old.
- Judges' reviews are worded as the reviewer's rating, never ours, and concerns get the same weight as praise.
- The message for work, school and neighborhood groups uses official links only, never this guide. Friends, family and public posts may get the guide (Kevin, Oct 20).

## The save-link and storage contract

Changing any of this silently loses people's picks. `tests/model.mjs` pins it (a golden link, a real pre-ranked-choice link from the live site, round trips).

- localStorage key `vg2`, ballots keyed `ST|place+place` (or `ST|-`). Add fields to `BallotState` only (old saves are back-filled); never rename or remove one. `away` (Oct 29: the places this ballot's ZIP opens that the voter isn't in, by their answer or their address's county; another ZIP clears it) is never in the link.
- `vg-asked` (Oct 25) is separate and holds no picks: one-tap requests from this device (`p:<place id>` or `z:<ZIP>` to the day sent), dropped after three days (`model/coverage.ts`). Never put it in `vg2` or the link.
- `vg-adds` (Oct 28), no picks either: Add a source requests from this device, five at most, three days (`model/adds.ts` has the fields; never the contact). Never in `vg2` or the link. A source one brings in before the merge comes from its branch preview, in memory only; its id sits in `sources` like any switch, and `decodeShare` reads a held id's hash back even before the preview answers (the link's format is unchanged).
- Links live in the hash: `#v1~ST~places~zip~picks~districts~notes~sources`; `v2` adds `~ranks` only when a ranking exists; a 10th field `~notMine` is written only when the voter hid "may apply" races (an empty ranks slot fills field 9). An 11th field `~lens` (Nov 3) writes `sources` as a recipe when that makes the link shorter: letters for sets read from the data when the link opens (`a` all, `d` defaults, `p l r u` the four chips) plus `+hash`/`-hash`; field 8 is then empty, so an older client opens every pick with the default lens. The letters are resolved against the data and `model/lens.ts` when the link opens, both ways (a source added to a chip later shows up, one re-rated out of it drops off), never cover a source still in preview (it travels as its own `+hash`), and picks never depend on them. The head never changes for it (a `v3` would also slip past the `v[12]~` scrubbers in `errors.ts` and `scrub.ts`). Hashes are FNV-1a base36 (`util.hash`), pick codes `Y N S D P` or a 3-char candidate-name hash. Keys are item ids or `id|candidate name` (multi-judge, multi-seat).
- Pick values: candidate names, `YES`/`NO` (measures and judges: keep is `YES`), `SKIP`, `DONE`, `PICK`. Lenses are stored as an explicit endorser-id list in `sources` (`null` = defaults); chips are presets over it.

## Test hooks (keep them, or update the tests in the same change)

The browser tests find the page by its ids, classes and data attributes (`data-act` on every control, `id="i-<item id>"` and `data-item` on every item, `data-fk`, `data-husk` and many more). Before you rename or remove one anywhere in `src/`, look it up in `tests/HOOKS.md`, which lists each with what it marks, and grep `tests/` for it.
