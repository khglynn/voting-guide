# Voting guide: agent instructions

*Last verified: 2026-10-19 (ledger v1).*

A public, one-page guide to the Nov 3, 2026 general election for Kevin's friends and family: enter a ZIP, see the next step and its date, every item on your ballot as a row with your trusted sources' picks beside it, decide, and leave with a cheat sheet. Live at https://vote.kevinhg.com (since Oct 19, 2026; the original https://voting-guide-silk.vercel.app still serves the same site). Vite + vanilla TypeScript, no framework, no cookies, no accounts; crash reports go to Sentry, errors only and scrubbed, and visits are counted with Vercel's cookie-free Web Analytics, nothing personal sent (both below). This repo is public: nothing private goes in it.

## Run and test

Node 20+. If `node --version` shows an old version, prefix commands with `export PATH=/usr/local/opt/node@22/bin:$PATH;` (a stray 2016 node at `/usr/local/bin` shadowed the real one on Kevin's personal Mac until Oct 19, 2026). Use preview ports 4173 to 4189: Node's `fetch` refuses a few ports on the web's "bad ports" list (4190 is one, as are 6000 and 6665 to 6669), and the sweep then fails with "bad port".

```sh
npm ci && npm run playwright:install
npm run build                      # data bundles + typecheck + production build
npx vite preview --port 4173       # then, against it:
npm run test:model                 # contracts, no browser: save links, districts, lenses, verdicts, fills (~1s)
npm run test:e2e                   # scripted taps at 380px (~2 min)
npm run sweep                      # every ballot the guide can show (68) checked against the data; MODE=full for every district variant
node tests/perf.mjs                # biggest ballots at 4x CPU throttle: taps must paint under 250ms
npm run shots                      # review screenshots of the test ballots into .tmp/shots/ledger/
scripts/ship.sh --gates-only       # all local gates in one go
```

Crash-report checks in the e2e need a build with a DSN: `VITE_SENTRY_DSN=https://0e2e0e2e0e2e0e2e0e2e0e2e0e2e0e2e@o0.ingest.us.sentry.io/0 npm run build`, then `SENTRY_E2E=1 npm run test:e2e` (CI and `ship.sh` do both; project 0 takes nothing).

`BASE` points any browser check at another server (a Vercel preview, production). `?today=2026-11-03` pretends it's that date. `?try=fresh|aunt|straight|sources` shows a scenario on whatever ballot opens and never saves anything.

## Where things live

- `data/` is the only copy of the research data. `scripts/build-data.mjs` validates it into `public/data/` bundles (bad records are skipped and reported, never fatal) and counts each place's and state's coverage into `index.json` (`scripts/coverage.mjs`: sources on that ballot, how many with picks, local ones, its own races with any pick, the newest row date; `tests/model.mjs` pins them to the app's own ballot); `scripts/check-data.mjs` and `scripts/check-addresses.mjs` are the data gates. New optional fields must be passed through and shape-checked in build-data and typed in `src/types.ts`. An endorser's `blocked: true` with a one-line `blocked_note` (Oct 25) marks a source whose site shows a bot check to anything that isn't a browser; it reads like a paywall ("Couldn’t read").
- `src/ballot.ts`, `src/state.ts`, `src/geo.ts`, `src/util.ts`: the model. `buildBallot` decides what is on a ballot (statewide items, place items, district questions, "may apply"). Don't replace it with a shortcut over `place.order`.
- `src/model/`: rules the views use. `labels` (titles, seat labels, courts, pick words, pass thresholds), `lens` (the chip presets over your sources, in step 2 and the ballot's Edit sheet), `tally` (the verdict column), `bulk` (fills with undo), `judges` (official reviews and the section's plain answer), `plan` (the next step from the state file; a place's own `early_in_person` window wins over the state's when every place on the ballot agrees), `coverage` (how covered a ballot is in plain words, the thin-place rule, and one-tap requests remembered per device), `adds` (a requested source on the requester's ballot before the merge, from its branch preview; `app.ts` swaps it in place, never through `resetUI`), `address` (what a Census match sets: district questions, "may apply" races on or off the ballot as `mine` or `notMine`, and the "Set from your address" line kept as `addrNote`, which names only the races the address put on the ballot; never the address).
- The address lookup asks the Census for every layer (`layers=all`): the newest Congress and legislature maps, the county, and the school district. `model/address.ts` settles Congress, the legislature and one school district's races (`schoolOf`: an "ISD" or "Unified School District" named in the scope). Trustee, council and commission districts aren't in the Census; a place's district maps settle them (next line).
- District maps (Austin and Travis County Oct 21; Williamson County, for Round Rock, Pflugerville and Williamson-side Austin, Dallas County and Harris County for Houston, Oct 26): `data/maps/{area}/{kind}.topojson` with its record `{kind}.json` (source, dates, the places whose ballots read it, and `settles`: rules of office, scope and the district a feature names). `scripts/maps/pull.mjs <area>` writes both from a manifest in `scripts/maps/manifests/` and fails a layer unless the simplified map answers like the original, other official copies agree, and public buildings (`scripts/maps/test-points.json`, never a home) get the server's own answer (a layer published as a zipped shapefile, like the Texas Legislative Council's SBOE plan, is read with mapshaper, kept whole within a buffer around its county, and checked against its own lines; a county's coded precinct layer can be merged by its codes, `dissolve`, so Dallas's 791 precincts ship as 28 pieces and Harris's 1,224 as 37, each carrying commissioner, JP and SBOE); mapshaper is pinned in `scripts/maps/package.json`, apart from the site's install. build-data lists each place's maps in its bundle (`maps`) and copies them to `public/data/maps/`; check-data errors on a rule no race reads and on a race a rule claims that no feature names. The app loads a ballot's maps only after a lookup (warmed while the Census answers, and from the first page as soon as the Census names the place, by the index's `maps`; a map that hasn't answered in 6 s is aborted and asked again next time), paints the Census's answers first and folds each map in as it arrives, and checks two witnesses, the Census's point and its 2020 block's interior point (`model/maps.ts` `answerAt`): agree, settled; disagree with the point within 30 m of a line, the block's answer; otherwise no guess ("right at a ... line" or "We couldn't tell your ..."). A city's map (a record with no `county`) is the exception at its outer edge (`edgeOf`): city limits move with annexations and cut 2020 blocks, so one witness inside the city and one outside is never settled by the block. `model/address.ts` settles what the answers name the way it settles Congress (`districts`, `mine`, `notMine`), and a one-county map's county races come off for another county's address (on a ballot that lists two counties' races, like Pflugerville's, each county's map answers its own county's addresses), named as that county's in "Not on your ballot" ("Travis County Justice of the Peace"), while the box says the voter's own county races aren't the ones listed. A map never overwrites the voter's own answer or "not on my ballot" (anything not in `addrSet`; "Not sure" isn't an answer). Every lookup first undoes what the last one settled (`addrSet`: the question keys and the "may apply" race ids it moved; a voter's own change takes an item out), so a corrected address keeps nothing it can't establish. Every claim the voter makes during a lookup (an answer, Change, "Not sure", on or off, whatever the question or race was before) stays out of every later pass of it (`lookupPasses`), Census or map; `claimAnswer`, `claimOn` ("It's on my ballot", kept in `mine`) and `claimOff` are the voter's changes, called by actions.ts and by the tests alike. Pull again before an election: counties split precincts (check-data warns 30 days after a pull).
- Poll times are local: `plan.ts` keeps each state's time zones, the main one first. A new place in a state's other zone (Pensacola is Central in Eastern Florida) needs a line in `PLACE_ZONE`, or its "polls closed" moment is an hour off.
- `src/views/`: string templates. `render.ts` paints regions and single rows; `actions.ts` holds every `data-act`; `app.ts` the flows; `main.ts` boot and the tap handler (tuned on phones; keep it).
- `src/motion.ts`: the little motion there is. A tapped row's header stays put while its panel grows open (200ms) and folds away (160ms); a pick draws its tick; jumps glide and mark where they land; sheets slide; under "Hide races I've decided" a decided row shows its pick for a beat (`BEAT_MS`, 900ms, in `actions.ts`), then folds away (220ms) while the rows under it slide up, or its finished section folds under its band. Everything else a tap opens or closes in place (a section folding under its band, "Show" lines, the plan's details, the address form, the first page's switches, "Not on your ballot") goes through `glide`, which moves each named box from its old height to its new one (Kevin, Oct 21: nothing should snap). Only transform, opacity and one container's height animate, through the Web Animations API, so a repaint just drops an animation in flight; under `prefers-reduced-motion` everything lands at once in the same end state.
- Crash reports (Oct 25): `src/errors.ts` (main bundle, imported first) keeps the problem report's errors and, once the page has loaded and gone idle, fetches `src/sentry.ts`, a chunk of its own (about 24 KB gzipped), only in a production build with `VITE_SENTRY_DSN` (Vercel production and preview). `src/scrub.ts` holds what may leave; read its header before changing anything there, since the How text's privacy line promises it. The address check is one rule that fails closed (`errors.holdsPrivate`); keep it one rule. The chunk imports nothing from the page's bundle, so a start-up crash still reports. Source maps only with `SENTRY_AUTH_TOKEN` (never `VITE_`), deleted after upload. Off switch: remove `VITE_SENTRY_DSN` in Vercel and redeploy. https://khg-y1.sentry.io/projects/voting-guide/
- Visit counts (Oct 28; Kevin: "I would like the telemetry ... Let's turn it on."): `src/stats.ts` loads `@vercel/analytics` (the loader pinned; Vercel serves the script itself) only when the host is `kevinhg.com` or `*.vercel.app`, once the page has loaded and gone idle, from a chunk of its own (about 1 KB gzipped), so local dev, `vite preview` and the tests never load it. Vercel's script sends `location.href` whole; `beforeSend` (`cleanUrl`) cuts it to origin and path and drops an event whose path still holds five digits in a row or an at sign (only the path: a preview's host can hold five digits). The referring site goes as its origin only: Vercel's script reads `document.referrer` after `beforeSend` and sends another site's whole (the linking site decides how much that holds; our Referrer-Policy only governs links out), so `startStats()` shadows `document.referrer` on the page with `referrerOrigin` before the script loads, and loads nothing if that doesn't take. Pushing a view keeps the path, so Vercel's own pageview fires once per load; the screens are counted as events. `track(name, data)` sends four events, typed in `stats.ts` `Events` and the dashboard's vocabulary, so keep names and values stable: `ballot` `{ state, how }` (the state code only, never the place: Ballwin, Clayton and Webster Groves each come from one ZIP in the index, as does every set of several places like DC's wards or Aurora and Denver, so a place would name the ZIP typed, while any ZIP in a state opens at least its statewide ballot; how `zip`, `address`, `shared`, `returning`, `list`), `request` `{ kind }` (`city`, `picks`, `source`, `report`, `follow_up`, only once the post went out), `view` `{ name }` (`start`, `ballot`, `plan`, `share`, `reader`, on each change of screen, `app.ts viewed()`), `share` `{ act }` (`made`: the "Save a link to my picks" panel opened, each time it opens; `opened`: a save link opened a ballot). A value must be a short plain token and never holds five digits in a row, or the event is dropped: never a ZIP, an address, a Census answer, a pick, a contact or anything typed. On a Vercel host, events from before the script loads (a save link or a returning ballot opens during boot) wait in memory and go once it has. The How text's "Your privacy" item promises all this (model tests pin its words). e2e, sweep, perf and shots answer `/_vercel/insights/*` with an empty script, so a run against a preview or production never fetches the real one; the e2e's visit-count blocks stub `window.va` on localhost and serve the build as vote.kevinhg.com with a stand-in script that builds its payloads the way Vercel's does, to run the whole path (an incoming referrer with a ZIP in its query included). Off switch: turn Web Analytics off for the project in Vercel, or take `startStats()` out of `main.ts`. Dashboard: https://vercel.com/kevinhg/voting-guide/analytics
- `tests/`: `model.mjs` + `model-ledger.mjs`, `e2e.mjs`, `sweep.mjs`, `perf.mjs`, `shots.mjs`.
- The look is three materials: paper (Blender renders in `public/paper/`, made by `scripts/paper/`; the sheets' torn bottom `sheet-bot.webp` is `sheet.webp` flipped, and the bottom bar's torn top is cut from the same outline; its README says how to regenerate, and `bake.py` writes the block between `paper:start` and `paper:end` in `src/styles.css`, so don't hand-edit it), one printed green ink for headings (Archivo, with a speck mask), and pen for rules, boxes and ticks. ## How changes ship

Branch, pull request, CI (`.github/workflows/ci.yml`: data gates, model tests, build, e2e, sweep), an independent review, then a squash merge. Pushes to `main` deploy to the live site, and friends are using it during early voting, so nothing merges without the gates green on the final commit. Vercel builds a preview for every branch (`voting-guide-git-<branch>-kevinhg.vercel.app`); run the sweep against it before merging.

### Test in proportion to the change

Kevin, Oct 20: tests were costing a lot of time, money and compute. CI runs every gate on every pull request at no cost (the repo is public), so local runs only need to catch sooner what CI would catch, not repeat it. The expensive parts are multi-agent reviews and full local gate runs every round.

- **Copy, CSS or data wording:** `npm run build` (the typecheck) and `npm run test:model` (about 1s). Push; CI does the rest.
- **A view or a flow:** those two, plus a short script or the e2e block that covers the change. Push; CI runs the full e2e and sweep.
- **Ballot building (`ballot.ts`, `geo.ts`), the save link or storage, districts, or data shape:** the full local gates (`scripts/ship.sh --gates-only`, with `--full` for district changes) before pushing.
- **`tests/perf.mjs`:** only when render or tap paths change.
- **Review:** one reviewer for routine work. Run a multi-agent review (opus; Fable only with Kevin's OK) only for storage, ballot logic or the address lookup, and stop it once it has answered the question.
- **Don't rerun a gate that passed on the same code.** The bar for merging doesn't change: CI green on the final commit.

## Rules that do not bend

The reasons are in the workbench's FOUNDATION.md.

- No real person's street address anywhere: data, code, tests, notes. Public offices and polling places only, through the allowlist.
- Every fact has a source URL. Confidence is marked honestly (verified, sourced, unverified).
- Nonpartisan and parallel: the same fields for every candidate, quote rather than characterize, no recommendations from us. The default lens is papers and nonpartisan guides; anything partisan is the voter's choice.
- Lean labels come only from outside ratings, official party status or a group's own stated mission, never from whom it endorses.
- Endorsement states stay distinct: endorsed, took no stand, no picks found, not checked yet.
- No red or blue in the UI; party is text, lean is a neutral five-step scale plus a word. Color has one job each: gold = your pick, sage = your sources agree, clay = they disagree, dusk = the frame and official reviews.
- No all caps (no `text-transform: uppercase`), no em dashes in guide copy, plain words for a smart 16-year-old.
- Judges' reviews are worded as the reviewer's rating, never ours, and concerns get the same weight as praise.
- The message for work, school and neighborhood groups uses official links only, never this guide. Friends, family and public posts may get the guide (Kevin, Oct 20).

## The save-link and storage contract

Changing any of this silently loses people's picks. `tests/model.mjs` pins it (a golden link, a real pre-ranked-choice link from the live site, round trips).

- localStorage key `vg2`, ballots keyed `ST|place+place` (or `ST|-`). Add fields to `BallotState` only (old saves are back-filled); never rename or remove one.
- `vg-asked` (Oct 25) is separate and holds no picks: one-tap requests from this device (`p:<place id>` or `z:<ZIP>` to the day sent), dropped after three days (`model/coverage.ts`). Never put it in `vg2` or the link.
- `vg-adds` (Oct 28), no picks either: Add a source requests from this device, five at most, three days (`model/adds.ts` has the fields; never the contact). Never in `vg2` or the link. A source one brings in before the merge comes from its branch preview, in memory only; its id sits in `sources` like any switch.
- Links live in the hash: `#v1~ST~places~zip~picks~districts~notes~sources`; `v2` adds `~ranks` only when a ranking exists; a 10th field `~notMine` is written only when the voter hid "may apply" races (an empty ranks slot fills field 9). Hashes are FNV-1a base36 (`util.hash`), pick codes `Y N S D P` or a 3-char candidate-name hash. Keys are item ids or `id|candidate name` (multi-judge, multi-seat).
- Pick values: candidate names, `YES`/`NO` (measures and judges: keep is `YES`), `SKIP`, `DONE`, `PICK`. Lenses are stored as an explicit endorser-id list in `sources` (`null` = defaults); chips are presets over it.
