# Results fetcher: agent instructions

*The root `AGENTS.md` covers the site and its rules; this is the Worker's own detail, moved out of the root file on 2026-11-13 so the root fits what Codex reads.*

Results fetcher (Nov 3, 2026; plan in the workbench's (`~/DevKev/personal/voting-guide-workbench`) `claude-plans/2026-11-03-results/PLAN-PHASE-1.md`): `results-worker/` is a Cloudflare Worker (`vg-results` on Kevin's personal account, https://vg-results.kevinhg.workers.dev) that reads official county feeds on a one-minute cron and serves `/results/2026-11-03/{ST}.json` (30 s cache), a preview file per state and `/results/status`. It deploys with `results-worker/deploy.sh` (refuses any other Cloudflare login), never with the site, and data never goes through a pull request. Plain JavaScript under `src/` so the same module runs under node (`bin/run.mjs`) and the tests (`npm test` in this folder, its own CI job). One map per county in `results-worker/maps/` pairs feed contests with guide items: `bin/map-inputs.mjs`, an Opus draft, a blind Opus judge, `bin/map-assemble.mjs` (which folds the agreed pairs into the map; `--statewide` for a county's slices of statewide races, `--replace` to rebuild a made map's own pairs), then `bin/map-check.mjs --write` (which also regenerates `src/maps.gen.js`); a county's numbers go public only once a first-run check stores `checked:{id}` in KV with the map's check hash, as `bin/map-check.mjs` prints it (not its map hash, which differs on maps with a runoff-rule race). A county map may carry a statewide race only as that county's slice (`statewide: true`, reaches [county, "other counties"], never whole; `bin/map-lint.mjs` refuses any other shape, and any county map it can't check against its state's bundle, and `src/merge.js` reads a statewide pair that way whatever the map says): beneath the state's count, or on its own and named by county, counting with "other counties" missing, when the state has no count to show (refused, a link or not checked yet; also not read yet or at zero, added by the Nov 4 statewide review). Kevin's call on Nov 4, after Pennsylvania's and California's state sites refused the Worker, as the results plan records it (the workbench's `claude-plans/2026-11-03-results/DESIGN.md` rule 9 and `phase-1-log.md` entry 90); his own words weren't kept. Those slices carry their own `guide.statewide_fingerprint`, so a guide edit to a state item drops only them and never the county's own races. Its alerts (a source refused, a falling total, a map out of date) go to #gabby-log as replies under one post per election, never to Kevin's DM (Kevin, Nov 4: "They can all sit under one post in gabby log"; `src/ping.js`, Worker secrets `SLACK_BOT_TOKEN` and `SLACK_LOG_CHANNEL`).
